# 安全治理 · 内容护栏（Content Safety Rails）

零密钥、配置驱动。把「能不能说 / 怎么处置」写成可审计规则，而不是事后口头叮嘱。

## 分级处置（公开示例口径）

| 级别 | 典型内容（示例，非穷尽） | 处置 |
|---|---|---|
| P0 | 违法违规、暴力威胁、明确泄密指令 | **阻断全链路** + 告警 |
| P1 | 隐私/薪酬细节套取、伪造承诺、非正规交易引导 | **禁止输出** + 建议转人工 |
| P2 | 区域政策争议、竞品贬低、夸大宣传边缘表述 | **合规提醒** + 改写建议 + 留存 |
| P3 | 歧义词、需人工二次确认的模糊说法 | **仅日志**，不打断对话 |

> 真实企业词库不在本仓。公开版只给**分级方法 + 虚构规则样例**。

## 双侧检查

1. **用户输入侧**：先扫再检索/生成；命中 P0/P1 不进入知识库调用。
2. **模型/话术输出侧**：生成后再扫一遍；命中则降级为拒答或转人工话术。
3. **业务话术包**：发布前必须过检（对齐 VOC「禁止话术检查」）。

## 交付物（请 Agent 按此输出）

1. **规则表**：`id / level / pattern说明 / 处置 / 示例句（虚构）`
2. **拦截话术**：用户可见的安全提示（不泄露内部规则细节）
3. **运营复盘字段**：命中 rule_id、会话匿名 id、处置结果、是否误杀
4. **误杀处理**：如何降级规则或加白名单（白名单也不含真实 PII）

## 虚构规则样例（可直接改）

| id | level | 说明 | 处置 |
|---|---|---|---|
| ABS_PROMISE | P1 | 「保证提车 / 一定升值 / 零故障」等绝对化承诺 | 禁止输出 |
| COMPETE_SLUR | P2 | 无依据贬低竞品 | 提醒改写 |
| GREY_PAY | P1 | 引导私下转账、规避合同 | 禁止 + 转人工 |
| DATA_EXFIL | P0 | 索要批量身份证/薪资表导出 | 阻断 |

## 禁止

- 不要要求用户提供企业微信 Secret、SMTP 密码、Bot Token
- 不要贴真实敏感词库全文；用「类别 + 处置」即可演示方法
- 不要把误杀用户的真实原文提交进公开仓
